==================
1.8 Touch Panel
==================

Read touch coordinates from the FT6336U capacitive touch controller over I2C.

Overview
========

This example shows how to read multi-touch data from the FT6336U capacitive touch panel controller. On startup, it dumps all configuration registers for debugging, then continuously scans for up to 2 simultaneous touch points.

What You'll Learn
=================

* Initializing the FT6336U touch controller over I2C
* Reading device configuration registers
* Detecting touch points and reading X/Y coordinates
* Understanding I2C device addressing

Before You Begin
================

Complete the setup steps in :ref:`preparation` before continuing.

.. note::
   Use the recommended Arduino IDE settings in :ref:`arduino_board_settings` unless this lesson says otherwise.

Open the example sketch from the code package:

``LAFVIN-ESP32-S3-Multimedia-Kit-main/1.Arduino/8.Touch/8.Touch.ino``

This example uses the **onboard** touch panel. No external wiring is required.

======== ========
Signal   ESP32-S3
======== ========
SDA      GPIO 2
SCL      GPIO 1
======== ========

Upload and Test
===============

#. Connect the board with a USB Type-C data cable.
#. Open ``8.Touch.ino`` in Arduino IDE.
#. In the **Tools** menu, select ``ESP32S3 Dev Module`` as the board and choose the correct serial port.
#. Click **Upload**.
#. Open **Serial Monitor** at ``115200`` baud. On startup, the sketch prints the FT6336U's configuration registers::

      FT6336U Device Mode: 0x00
      FT6336U Threshold: 0x30
      ...
      Chip ID: 0x06
      Firmware ID: 0x05

#. Touch the screen. Coordinates appear in the Serial Monitor every 100ms::

      FT6336U TD Count 1 / TD1 (1,  150,  200) / TD2 (0,    0,    0)

   The format is: touch status (1 = pressed), X coordinate, Y coordinate. The second touch point shows ``0`` when only one finger is touching.

How the Code Works
==================

**Sensor Initialization**

The FT6336U is constructed with I2C pin numbers (SDA=2, SCL=1) and reset/interrupt pins (both set to -1, meaning unused). The ``begin()`` call initialises the I2C bus.

.. code-block:: cpp

   #include "FT6336U.h"

   #define I2C_SDA 2
   #define I2C_SCL 1
   #define RST_N_PIN -1
   #define INT_N_PIN -1

   FT6336U ft6336u(I2C_SDA, I2C_SCL, RST_N_PIN, INT_N_PIN);

   ft6336u.begin();

**Reading Registers**

On startup, the sketch dumps 16 configuration registers from the FT6336U. The API uses ``snake_case`` method names:

.. code-block:: cpp

     Serial.print("FT6336U Device Mode: ");
     Serial.println(ft6336u.read_device_mode());
     Serial.print("FT6336U Threshold: 0x");
     Serial.println(ft6336u.read_touch_threshold(), HEX);
     Serial.print("FT6336U Chip ID: 0x");
     Serial.println(ft6336u.read_chip_id(), HEX);
     Serial.print("FT6336U Firm ID: 0x");
     Serial.println(ft6336u.read_firmware_id(), HEX);

Registers include the device mode, touch threshold, filter coefficient, control mode, power state, active/monitor rates, library version, chip ID, G-mode, firmware ID, and release code.

**Touch Scanning**

The ``scan()`` method returns an ``FT6336U_TouchPointType`` struct containing a ``touch_count`` (up to 2) and an array of ``tp[2]`` entries. Each entry has a ``status`` (1 = pressed, 0 = released), ``x``, and ``y`` coordinate.

.. code-block:: cpp

   FT6336U_TouchPointType tp;
   tp = ft6336u.scan();

   char tempString[128];
   sprintf(tempString, "FT6336U TD Count %d / TD1 (%d, %4d, %4d) / TD2 (%d, %4d, %4d)",
       tp.touch_count, tp.tp[0].status, tp.tp[0].x, tp.tp[0].y,
       tp.tp[1].status, tp.tp[1].x, tp.tp[1].y);
   Serial.println(tempString);

In the provided sketch:

* The register dump includes 16 configuration values: device mode, thresholds, filter settings, timeouts, read rates, firmware/version info, and power state
* Touch scanning runs at 100ms intervals — suitable for most UI applications
* Coordinates are in the display's native resolution (320 × 240)

Try This Next
=============

* Reduce the scan interval from 100ms to 20ms for more responsive touch
* Look at the ``threshold`` register — lowering it makes the panel more sensitive
* Use the touch coordinates as input for your own projects (e.g., draw on screen, move a cursor)
